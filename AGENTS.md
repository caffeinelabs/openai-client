# AGENTS.md

A Motoko client library for the OpenAI REST API, distributed as a [mops](https://mops.one) package (`openai-client`).

## Generated code — do not hand-edit

Nearly all source is generated by the [OpenAPI Generator](https://openapi-generator.tech) (Motoko client generator). Do not manually edit generated files; changes belong in the generator/spec and will be overwritten on regeneration.

- `src/Apis/*.mo` — one module per API group (Chat, Completions, Models, Embeddings, Images, Audio, Moderations, Files), each exposing free functions and a config-bound suite class.
- `src/Models/*.mo` — generated request/response type definitions.
- `.openapi-generator/FILES` — manifest of generator-owned files.
- `.openapi-generator-ignore` — patterns exempting files from regeneration overwrite.

`src/Config.mo` holds the shared `Config`/`Auth` types and `defaultConfig`.

Note: this package ships a **curated subset** of the upstream OpenAPI surface (see the "API Subset" section of `README.md`). The `README.md` model/API lists include entries not present in `src/`; the shipped `src/` tree is the source of truth for what exists.

## Toolchain

- Motoko compiler is pinned in `mops.toml`: `moc = "1.4.1"`. Match this version.
- Dependencies and versions are declared in `mops.toml` and locked in `mops.lock`; keep the two in sync when changing dependencies.
- `serde-core` is a specific fork pin (see the comment in `mops.toml`); do not replace it with the upstream package.

## Publishing scope

`mops.toml` restricts published files to:

```
files = ["src/Config.mo", "src/Apis/**/*.mo", "src/Models/**/*.mo"]
```

Code intended to ship must live under those paths.

## Not present in this repo

There is no CI workflow, `Makefile`, test suite, or lint/format configuration checked in. Do not invent build, test, lint, or format commands — none are defined here beyond the mops toolchain above.
