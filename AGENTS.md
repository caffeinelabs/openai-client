# AGENTS.md

A Motoko client library (`openai-client`) for the OpenAI REST API, distributed as a [mops](https://mops.one) package for the Internet Computer.

## Generated code — do not hand-edit

The entire `src/` tree is generated by [OpenAPI Generator](https://openapi-generator.tech)
(Motoko client codegen). The generated file manifest is `.openapi-generator/FILES`
and the generator version is pinned in `.openapi-generator/VERSION`. Do not hand-edit
any file listed in `.openapi-generator/FILES`; regenerate instead, and preserve the
exclusions in `.openapi-generator-ignore`. `src/` ships only a curated subset of the
upstream API (see the "API Subset" section of `README.md`).

## Layout

- `src/Apis/` — one module per API group (Chat, Completions, Models, Embeddings, Images, Audio, Moderations, Files).
- `src/Models/` — generated request/response data types.
- `src/Config.mo` — `defaultConfig` and the client configuration record.

## Toolchain and dependencies

- The Motoko compiler is pinned: `moc = "1.4.1"` in `mops.toml` (`[toolchain]`). Use that version.
- Dependencies and their exact versions are declared in `mops.toml` and locked in `mops.lock`.
  Run `mops install` to fetch them; they are vendored into `.mops/`, which is git-ignored and must not be committed.
- `serde-core` is pinned to a specific fork/version in `mops.toml`; keep that pin — the standard
  release does not have the features this package relies on.

## Conventions

- Keep `mops.lock` in sync with `mops.toml`; commit both together when dependencies change.
- `package.version` in `mops.toml` is bumped per release alongside regeneration (see `CHANGELOG.md`).

There are no build, test, lint, or format scripts defined in this repository, and no CI
workflows under `.github/`. Do not invent such commands; the only automated config present
is `.github/CODEOWNERS`.
