# AGENTS.md

A Motoko client library (mops package `openai-client`) for a curated subset of the OpenAI REST API, targeting the Internet Computer.

## Generated code

- Everything under `src/` is generated by [OpenAPI Generator](https://openapi-generator.tech) (generator version in `.openapi-generator/VERSION`). Do not hand-edit generated files; regenerating overwrites them.
- `.openapi-generator/FILES` lists every generated file. `.openapi-generator-ignore` controls which files the generator is allowed to overwrite; add a path there to protect manual edits.
- This package intentionally ships only a subset of the upstream API (Chat, Completions, Models, Embeddings, Images, Audio, Moderations, Files). See the "API Subset" section of `README.md`. Do not add modules for pruned APIs unless they are regenerated as part of the curated subset.

## Layout

- `src/Apis/` — one module per supported API (e.g. `ChatApi.mo`).
- `src/Models/` — request/response types for the supported APIs.
- `src/Config.mo` — `defaultConfig` (base URL, cycles, auth) used by every API call.

## Toolchain and dependencies

- Build tool is [mops](https://mops.one). `moc` (the Motoko compiler) is pinned to the version in `mops.toml` under `[toolchain]`; honor it.
- Dependencies and exact versions are in `mops.toml`; the resolved lockfile is `mops.lock`. Install with `mops install`.
- `serde-core` is pinned to a specific fork for required patches — see the comment on that dependency in `mops.toml`. Do not replace it with upstream.

## Conventions

- `.mops/` is a dependency cache and is git-ignored; never commit it.
- Consumers import modules as `mo:openai-client/Apis/<Name>` and `mo:openai-client/Config`; keep that public path stable (see the `files` entry in `mops.toml`).
- API calls make IC HTTP outcalls and consume cycles; the canister must be funded before calling endpoints (see "HTTP Outcalls and Cycles" in `README.md`).
